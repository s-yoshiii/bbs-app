# 01 サインアップ・ログインactionのバグ修正

## What we built

- `src/actions/auth.ts` の `signup()` / `login()` Server Action を修正
  - `login()` で `formData` から `email` / `password` を取り出していなかったため、実行すると参照エラーになっていたのを修正
  - `signup()` 内で成功時に呼んでいた `redirect('/')` が `try/catch` の内側にあり、登録に成功しても常にエラーメッセージが返っていた不具合を修正（`redirect()` は `try` の外に移動）
- `database.sqlite`（TypeORM + sqlite3 のローカル開発用DBファイル）を `.gitignore` に追加（`*.sqlite`, `*.sqlite3`）

## Key concepts learned

- Next.js App Router の `redirect()` は、内部的に `NEXT_REDIRECT` という特殊な値を **throw** することでリダイレクトを実現している
- そのため `try/catch` の中で `redirect()` を呼ぶと、その throw が `catch` に捕まってしまい、「エラーが発生した」として処理されてしまう
  - 対策: `redirect()` は `try/catch` の外で呼ぶ、もしくは catch 内で `NEXT_REDIRECT` の digest を判定して re-throw する
- SQLiteのDBファイルのようなバイナリ・実行時生成物はソースコードではないため `.gitignore` で管理対象から外すべき（複数人開発時の競合・肥大化防止）

## Code patterns introduced

- Server Action での基本形:

  ```ts
  export async function someAction(formData: FormData) {
    const value = formData.get('key') as string;
    if (!value) {
      return { error: '...' };
    }

    try {
      // DB操作など、失敗しうる処理
    } catch (e) {
      console.error(e);
      return { error: '...' };
    }

    redirect('/'); // 成功時のリダイレクトは try/catch の外
  }
  ```

## Gotchas / things that broke

- `formData.get()` での値取得を忘れると、TypeScriptのコンパイル自体はスコープの問題で `tsc --noEmit` がエラーとして検出してくれた（`login()` の `email`/`password` 未定義エラー）
- `redirect()` を `try/catch` の中に置くバグは型エラーにも lint エラーにもならず、実際に動かして初めて気づきやすい種類のバグ
